# Yak — Agent guide

This file is a concise reference for AI agents (and humans) working on the Yak project.
It covers the project structure, tooling, and common workflows.

## Project overview

Yak is a small encoder-style transformer trained with masked language modelling (MLM),
then fine-tuned on a mix of general NLP tasks and evaluated for both accuracy and
calibration. The whole pipeline — tokenizer, pretraining, fine-tuning, evaluation —
is implemented from scratch with no black boxes.

The project is at an early stage, following a five-week plan documented in
[README.md](./README.md).

## File and directory organisation

```
├── pyproject.toml        # Project metadata, dependencies
├── README.md             # Full project documentation
├── AGENTS.md             # This file
├── uv.lock               # Lockfile (auto-generated by uv)
├── .python-version       # Python version pin
├── yak/                  # Main yak package
│   ├── __init__.py
│   └── tokeniser/        # BPE tokenizer subpackage
│       ├── __init__.py
│       └── bpe.py
├── tests/
│   ├── conftest.py       # Pytest configuration and path setup
│   └── tokeniser/
│       └── test_bpe.py   # Tests for the BPE tokeniser
└── .gitignore
```

Key points:

- The `yak` package lives at the project root. The `tokeniser` module is a
  subpackage under `yak/tokeniser/`.
- The `tests/conftest.py` adds the project root to `sys.path` so that the
  `yak` package is importable during tests.
- All project management uses `uv` — no `pip`, `pipenv`, or `poetry`.
- There is no `[build-system]` in `pyproject.toml` — this is an application,
  not a distributable package, so `uv run` skips the build step.

## This project is managed using `uv`

[uv](https://docs.astral.sh/uv/) is the single tool for dependency management,
virtual environment creation, and running commands.

The `pyproject.toml` defines:

- **`[project]`** — package metadata, Python version requirement (`>=3.13`),
  runtime dependencies (currently none).
- **`[dependency-groups]`** — optional dependency groups such as `dev`.
  Dev dependencies (like `pytest`) live here.

The `uv.lock` file is auto-generated and **must be committed** to version control.

## How to add dependencies

### Add a runtime dependency

```bash
uv add <package>
```

Example:

```bash
uv add numpy
```

This updates both `pyproject.toml` and `uv.lock`.

### Add a dev-only dependency

```bash
uv add --dev <package>
```

Example:

```bash
uv add --dev mypy
```

Dev dependencies are installed with `uv sync` (see below) but are not declared
as runtime requirements of the package.

### Install all dependencies after cloning

```bash
uv sync
```

This creates a virtual environment (`.venv/`) and installs all runtime and dev
dependencies per the lockfile.

### Add a new dependency group

Edit `pyproject.toml` directly under `[dependency-groups]`:

```toml
[dependency-groups]
dev = [
    "pytest>=9.1.1",
]
docs = [
    "mkdocs>=1.6",
]
```

Then run `uv sync` (with `--group docs` if needed) to lock and install.

## How to run the tests

```bash
uv run pytest
```

To run with verbose output:

```bash
uv run pytest -v
```

To run a specific test file:

```bash
uv run pytest tests/tokeniser/test_bpe.py
```

Tests are discovered under the `tests/` directory. The `conftest.py` in `tests/`
ensures the project root is on `sys.path` so that the `yak` package
(and its subpackages) are importable.
